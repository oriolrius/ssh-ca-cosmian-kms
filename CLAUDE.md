## Working with the technical reference

The `.docx` is the editable source of truth. Read its contents with:
```bash
pandoc --track-changes=all docs/technical-reference.docx -o output.md
```

Edit the document using the `document-skills:docx` skill (redlining workflow for substantive edits, direct OOXML editing for minor changes). After substantive edits, regenerate the Markdown rendering:
```bash
pandoc docs/technical-reference.docx -o docs/technical-reference.md \
  --track-changes=accept --extract-media=docs --wrap=none
sed -i 's#](docs/media/#](media/#g' docs/technical-reference.md
```

## Cosmian CLI

- **Binary**: `/usr/local/bin/cosmian` (version 1.9.0)
- **PKCS#11 provider**: `/usr/local/lib/libcosmian_pkcs11.so` (installed from the Ubuntu 22.04 release zip — see README)
- **KMS server version subcommand**: `cosmian kms server-version` (not `version`)
- **Config file**: `~/.cosmian/cosmian.toml` with `[kms_config.http_config] server_url = "..."`

## Key Technical Decisions Documented

- **ECDSA nistp256 for CA keys** (not Ed25519): PKCS#11 v2.40 compatibility for HSM/KMS integration; Ed25519 requires PKCS#11 v3.0
- **Dual-CA architecture**: separate User CA and Host CA to limit blast radius
- **Cosmian KMS integration**: CA key never exists as a file on disk; signing via PKCS#11 provider `libcosmian_pkcs11.so`
- **Ansible pattern**: private key generated on node (never traverses network), public key signed on controller via ssh-agent with `use_agent: true`
